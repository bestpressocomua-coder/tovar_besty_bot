# Bestpresso · Заявки — Telegram-бот

Бот для формування замовлень і інвентаризацій у форматі бланків 1С (xlsx),
які надсилаються вкладенням у відділ обліку.

## Що вже реалізовано (каркас)
- Флоу: **Замовлення** / **Інвентаризація**
- Замовлення: Регіон → каталог (на весь філіал); для **Львова**: Регіон → локація → каталог
- Інвентаризація: Регіон → (Львів: підлокація) → локація → **автомат** → каталог (номенклатура типу автомата)
- Автопідстановка **замовника** (з таблиці за Telegram-ID) і **дати**
- Генерація xlsx-бланків (замовлення / інвентаризація) і надсилання отримувачу

## Структура
```
bot.py           — логіка бота (aiogram v3, FSM)
data_loader.py   — завантаження довідників із CSV
blanks.py        — генерація xlsx-бланків (openpyxl)
config.py        — налаштування (токен, отримувачі, шляхи)
data/
  catalog.csv    — номенклатура: group, subcat, name, type, unit, articul
  locations.csv  — локації: region, sublocation, address, inv, atype, model
  employees.csv  — замовники: telegram_id, name, role
```

## Запуск
1. `pip install -r requirements.txt`
2. Заповнити `config.py`:
   - `BOT_TOKEN` — токен від @BotFather
   - `RECIPIENT_ORDERS`, `RECIPIENT_INVENTORY` — chat_id отримувачів
3. `python bot.py`

## Що потрібно від відділу обліку
- **Експорт номенклатури з 1С з колонками `unit` (од. виміру) та `articul`** — зараз порожні
- **База замовників** (`employees.csv`): реальні Telegram-ID співробітників
- **Отримувачі** файлів (chat_id) для замовлень та інвентаризації
- Довідники ведуться вручну (можна тримати в Google Sheets і експортувати в CSV);
  після оновлення — команда `/reload` у боті

## Оновлення каталогу/локацій
Редагуєте `catalog.csv` / `locations.csv` (додали товар/автомат — додали рядок).
Код не змінюється.

## Обмеження за регіоном (хто що бачить)
У `employees.csv` колонка **regions** визначає, які регіони бачить співробітник:
- `*` або порожньо — бачить усі регіони (відділ обліку/адмін);
- один регіон (напр. `Львів`) — бачить лише його; бот пропускає крок вибору регіону;
- кілька регіонів через `;` (напр. `Львів;Філіал_Житомир`).

Точні назви ключів — у `data/_region_keys.txt`. Приклад:
```
telegram_id,name,role,regions
733493566,Дарʼя Яковенко,Відділ обліку,*
555111222,Технік Львів,Технік,Львів
777333444,Регіонал,Менеджер,Львів;Філіал_Житомир
```
Доступ до бота мають лише ID з цієї таблиці; regions лише звужує видимі регіони.

## Відправка на пошту (Gmail SMTP)
Замовлення й інвентаризації надсилаються **листом з вкладенням(и)** на EMAIL_TO.
Telegram лишається **резервом**: спрацьовує тільки якщо лист не пішов.

Налаштування (краще через змінні середовища на Render, щоб пароль не був у коді):
- `SMTP_USER` = bestpresso.com.ua@gmail.com
- `SMTP_PASSWORD` = **App Password** (16 символів; згенерувати в акаунті Google → Безпека → Паролі застосунків)
- `EMAIL_TO` = Stegaluk@bestpresso.com.ua
- (за замовчуванням) SMTP_HOST=smtp.gmail.com, SMTP_PORT=465

Тема й імʼя файлу:
- Замовлення: `Замовлення — {локація} — {дата} — {Замовник}`
- Інвентаризація: тема `Інвентаризація — авт {номери} — {локація} — {дата} — {Замовник}`,
  один лист = кілька вкладень (файл на кожен автомат).

Вимкнути пошту (лишити тільки Telegram): змінна `SEND_EMAIL=0`.


## Формат файлу (шаблон завантаження в 1С)
xlsx повторює структуру шаблону 1С:
- аркуш `TDSheet`; колонка A порожня; заголовок у 2-му рядку; дані з 4-го;
- колонки: **код · Товар · Кількість · одиниця виміру**;
- у файл потрапляють **лише обрані** позиції (з кількістю);
- жодних даних хто/коли/локація в тілі файлу — вони лише в **назві файлу**;
- **код** і **одиниця виміру** беруться з `catalog.csv` (колонки articul/unit),
  заповнені з експорту 1С за назвою.

Позиції без коду (код порожній, поки не додасте у catalog.csv → articul):
Лимонада Моршинська 0.33; Батончик Рошен; Вода Värska 0,75; Absolute AMINO MIX 600.
